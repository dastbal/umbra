# Architectural Decision Records — Umbra

Index of every decision record in this module. **Read this table first**, match
your task against the `Tags` column, and open only the records that match.
Reading all of them costs a lot of context and is only warranted on an explicit
deep audit.

When a record and the code disagree: the **code** is authoritative for what the
system does now, the **record** for why it was built that way. A disagreement
means the record needs an amendment — flag it instead of silently picking a side.

| [024](./ADR-024-umbra-as-a-read-only-mcp-server.md) | Accepted — amended 16× 2026-09-08, 2026-09-10 | `mcp`, `packaging`, `presentation`, `read-only`, `interoperability`, `startup`, `latency` | Umbra publishes read-only knowledge and no MCP write or command tools. A user-scoped Codex/Claude entry invokes globally installed `umbra`, resolves exactly one trusted root, then creates that root's one local `.umbra/` index and may warm embeddings in background. The handshake precedes provider work; semantic retrieval stays retryable until durable coverage is verified; a rootless client remains safe and status-gated. The SDK and TypeScript workspace parser are required runtime dependencies. `init`/`setup` never modify local `.mcp.json`; install hooks never modify consumer configuration. Umbra as an MCP *client* is deferred, not rejected. **Amended:** the launch route is part of the handshake — `npx -y` re-checks the registry on every launch, so the connect time runs 11.7 s to 24 s with outright failures between, and this repository's own entry ran it against the record's own words. An eager import of the indexer cost another 2.9 s before `connect`, which amendment 12's ordering could not reach. And readiness now asks whether the index can *answer* rather than whether it is *current* — 401 ms of full inspection per call became 52 ms, and an edited file no longer refuses the question, because the reply already carries the index's age. |
| [025](./ADR-025-embeddings-are-chosen-not-assumed.md) | Accepted — amended 2× 2026-09-02; §3 superseded by 026 | `rag`, `embeddings`, `ollama`, `vertex`, `storage`, `portability`, `migration` | The embedding provider is resolved at runtime and pinned at launch; each provider owns its own column in `code_chunks`, so two vector spaces can never be compared and one row carries both. | [026](./ADR-026-vectors-are-numbers-and-the-database-can-count.md) | Accepted | `rag`, `storage`, `performance`, `sqlite-vec`, `migration`, `portability` | Vectors are float32 BLOBs in a `chunk_vectors` table keyed by `(chunk_id, provider, model)`, and the cosine distance is computed by SQLite so only the top *k* rows ever become JavaScript objects. 5.3× fewer bytes, 14.7× faster to read, and memory flat in the index size; a provider is rows rather than schema, and a model upgrade is its own identity. Still a linear scan — indexed KNN is deferred. Supersedes ADR-025 §3. |

| [031](./ADR-031-measure-before-building.md) | Accepted — amended 5× 2026-09-08/09, 2026-09-10 | `evals`, `retrieval`, `quality`, `tokens`, `roadmap`, `cost`, `latency`, `embeddings` | Work is ordered by what can be measured, and what is off that path is frozen rather than grown.
